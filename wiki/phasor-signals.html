phasor-signals

信号层。模拟引擎只消费进场和出场的布尔数组；这些数组从哪来，以前是调用方的事，现在是这个 crate 的事。 这也是“能跑回测的引擎”和“能写策略的引擎”之间的差别。它做六件互不相同的事：把原始条件清洗成交替序列、从进场生成出场、 给信号在连续段里排名、把信号读成区间记录、为零假设生成可复现的随机信号，以及为机器学习生成会读未来的标签。

只依赖 phasor-core输入输出都是列主序的 &[bool] / &[f64]，和模拟层只通过数组衔接，没有 crate 依赖
5,782 行 fixture长度 ≤ 6 的布尔数组全部枚举，与 vectorbt 逐个对照；cargo test 直接回放
1 个模块读未来labels 是唯一的例外：它产出训练目标 y，永远不能当信号或特征喂给回测

从第一性原理看：从信息到决策

先不看代码。这一节回答：信号在量化研究里对应什么概念？如果从零实现这一层，它的形状应该怎样推出来？后面各节再讲 phasor 的具体选择。

1. 信号是什么

一个系统化策略可以拆成三段：信息（价格、因子）→ 决策（什么时候进、什么时候出）→ 执行（下多少、成交在哪）。 信号就是中间那段的输出：一个以时间为索引的决策序列。它只有一个不能违反的约束——因果性： t 时刻的决策只能用 t 时刻已经知道的信息。用 t 收盘算出的因子，最早只能在 t+1 交易，这就是“延迟”（delay）。

信号层位于信息和执行之间；它自己不碰价格之外的任何账户状态

2. 状态和事件不是一回事

“因子高于阈值”是一个状态：条件成立的每一根 K 线都是 true。但交易需要的是事件：条件开始成立的那一根。 把状态直接当信号，就是在条件持续期间每根 K 线都发一次“买入”。大多数会被忽略（已经有仓位），但不被忽略的那些（比如允许加仓时）会改变结果。 从状态到事件，就是信号处理里的边沿检测；而进场和出场两个数组一起，还需要一个状态机：空仓时只认进场，持仓时只认出场， 得到严格交替的 进、出、进、出。

需要事先决定的事可选做法推荐的默认
同一根 K 线既要进又要出进优先 / 出优先 / 都不要 / 交给执行层信号层两个都不要：数组没有表达意见，替它挑一个就是编造。真正的冲突要在知道仓位的执行层解决。
还没进过场就出现出场丢掉 / 保留默认丢掉：没有仓位的出场不是交易。只有偏空或已有持仓的列才需要保留。
序列开头就处在一段信号中间照常处理 / 丢掉这段按用途选：排名时，开头这段“已经进行到第几根”是未知的，丢掉更诚实。

3. 出场是进场的函数

进场通常来自外部条件，出场却往往依赖于具体那笔进场：持有 N 根后出场、从进场价跌 5% 止损、条件反转时出场。 所以出场生成的本质是：对每个进场，在它之后的一个窗口里，按某个选择规则挑一根 K 线。 时间出场、条件出场、随机出场，都是同一个循环配不同的选择函数。由此要回答三个问题：

窗口从哪开始

进场后至少等几根（wait）。等 0 根就允许同一根 K 线开仓又平仓，而大多数数据说不清那根 K 线内部先发生了什么，所以默认至少等 1 根。

窗口到哪结束

到下一个进场为止，每个出场就只属于一个进场；到列尾为止，窗口会重叠，一个出场可能同时“平掉”好几笔进场。要能回答“这个出场平的是哪笔”，只有第一种可以。

窗口里挑哪根

止损和阈值要第一根满足条件的；有些规则会选多根。选出窗口之外的 K 线是 bug，应当报错，而不是悄悄写进别人的窗口。

4. 信号本身也有结构

布尔序列回答的是“第 i 根有没有信号”，但人们真正问的是区间的问题：一段信号持续多久？两次信号隔多久？“连续第三个信号才进场”需要知道信号在段内排第几。 还有一个容易忽略的诊断：信号在样本里的平均位置。如果所有信号都挤在样本开头，常见原因是指标的预热期；挤在结尾，常见原因是未来函数，而不是发现了什么。 把区间做成记录（列、开始、结束、是否结束），就能和成交、交易用同一套统计工具；还在进行中的区间，其长度只是下界，不能和已结束的混在一起平均。

5. 零假设：和随机比

一个进场规则有没有价值，最直接的检验是：同样数量的随机进场能不能做到一样好。赢不了随机的规则只是样本。 随机数生成器的选择在这里是原则问题：顺序流（每次抽样依赖之前所有抽样）会让结果随列的遍历顺序、线程数、前面插入的列而变。 应该用基于计数器的生成：每次抽样是 (seed, row, col) 的纯函数，一列的结果与它旁边有什么无关，一个种子就命名唯一的答案。 更严格的零假设是“匹配的”：保持信号数量和段结构不变，只打乱位置。

6. 标签不是信号

机器学习需要训练目标 y：未来 N 根的收益、涨跌三分类、三重障碍（止盈、止损、时间上限谁先触发，López de Prado 提出）、zig-zag 拐点。 它们按定义读未来：t 时刻的标签由 t 之后的价格算出。所以它们与信号是对立的：信号必须因果，标签必须前瞻。 两件事要做对：标签绝不能流进回测；每个标签要说清楚它往前看了多远，因为训练集和测试集之间要留出至少这么长的间隔（purge），否则训练样本的标签会偷看到测试期的价格。

7. 如果从零实现，按这个顺序

  1. 统一数组约定。列主序、n_rows × n_cols，每列独立处理，绝不跨列读数据；形状不对直接报错。
  2. 清洗：边沿检测 + 进出状态机。输出严格交替；同根冲突两个都丢；“必须先进场”可配置。
  3. 出场生成：一个循环 + 可插拔的选择函数。参数化 wait 和窗口边界；校验选择结果在窗口内。在有泛型的语言里，选择函数可以零开销内联。
  4. 排名：两种计数分开。数信号（第几个 true）和数段（第几段），都支持外部重置和“跳过开头那段”。
  5. 区间：做成记录。每段一条（列、开始、结束、状态），持续时长按“已结束开区间、未结束闭区间”算，平均只用已结束的。
  6. 随机：计数器式生成。按概率、按精确数量、按交替的进出对三种；用性质测试（数量精确、严格交替、频率对）而不是和某个随机流逐位比较。
  7. 标签：隔离并标注前瞻长度。放在单独的模块，每个函数的文档写明往前看多少根；三重障碍额外返回“在哪一根决定的”。
  8. 与参考实现差分。布尔输入的难点在形状不在数值，所以短数组可以全部枚举，而不是随机抽样。

清洗：clean_enex

阈值化的因子在条件成立的每一根 K 线都发信号，而不是只在它开始成立的那一根。clean_enex 用一个三态状态机把一对数组压成严格交替： phase = −1 还没发过任何信号，1 持仓，0 空仓。空仓或未开始时只接受进场，持仓时只接受出场。 同一根两个都为 true 时两个都丢，而且这一根什么状态都不改。下面每格可以点击切换。

FirstSignal
点上面两行的格子切换输入；下面三行是 clean_enex_1d 的输出和每根 K 线之后的 phase

同根冲突两个都丢“不是遗漏”。一个同时说“进”和“出”的数组什么都没说，替调用方挑一个就是编造意见。 from_signals 有五种可配置的冲突模式专门处理这件事，它们属于那里：那里有仓位可以参照，而这里没有可以“相邻”或“相反”的东西。

生成出场：generate_exits

参考实现的生成器接受一个选择函数：给定半开窗口 [from, to) 和列号，返回要发信号的行。这是对的抽象：按时间、按止损、随机出场是同一个循环配不同的选择。 但参考实现自己的 Rust 后端做不到：Numba 回调传不进原生代码，它的分发器拒绝所有带回调的函数。 在 Rust 里回调是泛型参数 C: ExitChoice，单态化之后零开销，任何 FnMut(from, to, col, &mut Vec<usize>) 都自动实现它。

每个进场一条窗口：浅蓝是 [from, to)，绿色是进场，红色是生成的出场；被跳过的进场用虚线框
规则
ExitWindow

UntilNextEntry（默认）

窗口到下一个进场为止，所以每个出场恰好属于一个进场。只有这个模式能回答“这个出场平的是哪笔进场”，所以处处是默认。代价是：下一个进场来得太早时，前一个进场可能根本没有出场。

ToEndSkippingResolved

窗口到列尾，但落在已解决窗口内（行号 ≤ 上一个出场）的进场直接跳过。否则重叠的窗口会让同一根 K 线平掉好几笔进场。

ToEnd

每个进场各自找到列尾，完全独立。出场可以重合或交叉，于是没有一个出场属于某一笔进场。适合“每笔进场各算一次持有收益”的研究，不适合直接喂给单仓位模拟。

exit_after(bars) 把 wait 设为 bars、选择函数返回窗口第一根：wait 就是持有期。它是所有出场规则的零假设：出场赢不了“持有 n 根”的策略，只有进场规则和一个习惯。 exit_on(condition, wait) 取窗口里第一根 condition 为 true 的。两者都 pick_first = true。窗口超出列尾（to ≤ from）时这个进场没有出场。

wait 不是细节。同一根 K 线上生成的出场，意味着一个仓位在一根 K 线内开了又平，大多数数据支撑不了这个结论，大多数回测也不该声称它。 参考实现处处默认 wait = 1，这里一样；0 是允许的，但不鼓励。

generate_alternating：一起生成，而不是事后过滤

clean_enex 过滤已经存在的数组；generate_alternating 构造它们：每一步问一边“从 from 开始，下一根在哪”，再把答案交给另一边。 基于止损的出场属于这里，因为止损价取决于还没被选出来的那笔进场。选中第 r 根进场后，出场从 r + exit_wait 开始找；选中出场后，进场从 r + entry_wait 开始找； wait 为 0 时强制至少前进一根，否则同一根会被无限次选中。任一边找不到就结束这一列。

排名：信号在段里排第几

“连续第三个信号才进场”、“每次重置后跳过前两个信号”，都需要知道信号在段里的位置。输出是每个 true 一个整数，其余为 −1。 两个问题很容易混淆：signal_rank 数信号（第一个 true 是 0，下一个是 1，不管隔多远）；partition_rank 数段（第一段里的所有 true 都是 0）。 两者都接受可选的重置数组，让计数可以在行情切换时重新开始。

点格子切换；第二行是重置数组（黄色）。下面是三种排名和两个列级统计
LeadingRun

重置落在段中间，就从那一根重新编号

乍看会以为重置要等这段结束才生效，其实不然：XXXX 配重置 .X..，得到 [0, 0, 1, 2]，第 1 根成为新的 0。为防止过期的重置（发生在上一段结束之前的）在这一段再次生效，判断里有 reset_row > prev_run_end 这一条守卫。

LeadingRun::Skip

如果一列从一段信号的中间开始，它无从知道自己已经进入这段多远，此时的排名只是猜测。Skip 丢掉这一段，等到第一个 false 之后才开始计数：XX.XX 的 signal_rank 从 [0, 1, −1, 2, 3] 变成 [−1, −1, −1, 0, 1]。

nth_index(n)：每列第 n 个信号的行号，负数从尾部数（−1 是最后一个），没有则 −1。 normalized_average_index：信号平均行号缩放到 [−1, 1]，−1 全在开头、+1 全在结尾、0 均匀或居中；没有信号或只有一行时为 NaN。 它的 n_rows <= 1 判断是多余的（一行时缩放本来就除以零得 NaN），因参考实现有而保留，变异测试确认删掉不改变结果。

区间：把信号读成记录

布尔列回答“第 i 根信号开着吗”，人们问的却是区间：一段持续多久、两次信号隔多久、规则安静了多少根。区间就是记录： RangeRecords { col, start_idx, end_idx, status }，结构数组，id 不存储，与成交、交易同一种形状，所以同样的归约都能用。 同一个数组有三种读法：

点格子切换输入。每条横条是一条记录，从 start 到 end；虚线端表示 Open（到最后一根还没结束）

已结束按开区间、未结束按闭区间：end − start 对 end − start + 1。已结束区间的 end 是结束它的那一根，属于之后；未结束的没有这样一根，最后一个下标仍被它覆盖。 交易和回撤的持续时长是同一条规则，两套约定混用会让每个平均值偏差最多一根。未结束区间的长度仍然只是下界，把它和已结束的一起平均是低估“规则开着多久”的标准方式， 所以 mean_closed_duration 只平均已结束的，没有则 NaN。

函数一条记录是状态
partition_ranges一段连续的 true，从第一根到结束它的那根 false到最后一根还在进行的为 Open，end 是最后一根本身，不是它的下一根
between_ranges相邻两个 true 之间：从一个信号到下一个信号全部 Closed（两端都有信号）；只有一个信号的列没有记录
between_partition_ranges一段的最后一根到下一段的第一根全部 Closed。XX..XX：between_ranges 有 3 条，这里只有 1 条（1 → 4）

随机信号：键控，而不是流

流式生成器让每次抽样依赖之前的所有抽样，于是答案会随列的访问顺序、线程数、前面插入一列而改变。这里每次抽样都是 (seed, row, col) 的纯函数： SplitMix64 的输出混合函数套三层，mix(mix(mix(seed) ^ row) ^ col)，取高 53 位得到 [0, 1) 内可精确表示的浮点数。 所以一列的信号不管是单独生成还是作为扫描中的第一千列都一样，一个种子命名一个答案，也满足 AGENTS.md 里“串行和并行逐位相同”的规则。

下面每格都是用 JavaScript BigInt 逐位移植的同一个算法算出来的。改列数，看已有的列有没有变
函数

绿色是进场，红色是出场（random_entries_exits），灰色是信号（另外两个函数）。每行一列，横向是 K 线。

random_by_prob

每根独立以概率 prob 触发，uniform(seed,row,col) < prob。每列的个数服从二项分布，不固定。prob 不在 [0, 1] 或为 NaN 时报错。

random_n

每列恰好 n 个，位置无放回均匀抽取：部分 Fisher-Yates 洗牌，第 k 步把槽 k 与 k..n_rows 中抽到的槽交换，第 k 步的抽样键控于 (seed, k, col)。n > n_rows 报错。

random_entries_exits

每列抽 2n 个不同的行，排序后依次分给 进、出、进、出：每个进场的出场都在下一个进场之前，且没有一根两者兼有。2n > n_rows 报错。

这些不复刻参考实现的生成器：它们的结果取决于 NumPy 的随机流，Rust 里无法重现；差分 fixture 只会比较两个不同的抽样，然后因为错误的原因通过。 所以它们按性质测试：数量精确、严格交替、频率符合概率（10 万格上误差 < 0.01，约 7 个标准误）、同种子相同、换种子不同、一列不依赖它的邻居。 更严格的“匹配零假设”（同样数量、同样的段结构、只打乱位置）仍是一个设计问题，尚未实现。

标签：每个函数都读未来

这些是标签，模型要学着预测的 y。t 时刻的值由 t 之后的价格算出，这正是它的意义，所以它们没有一个是信号，没有一个能作为进场、出场或特征喂给模拟。 这样做的回测不是“乐观”，而是错的：它在用当时看不到的价格交易。crate 的其余部分都是因果的，这个模块是例外，每个函数都写明往前看多远， 训练/测试划分要留的间隔（purge）可以直接从签名读出来。
输入一列收盘价（逗号分隔，nan 表示缺失），调参数看四种标签

图上的三角形是 pivot_labels 确认的拐点（▲ 波谷 +1，▼ 波峰 −1）。点表格里的某一行 t，图上会画出它的三重障碍：上下两条水平线、右边的时间上限，以及决定它的那一根。

函数定义往前看边界
fixed_horizon_returns(h)close[t+h] / close[t] − 1h 根末尾 h 根和任一端为 NaN 时为 NaN；不会从下一列“借”价格。h = 0 报错：零根收益恒为 0，几乎总是调用方差一。
trend_labels(h, θ)收益严格 > θ 为 +1，严格 < −θ 为 −1，否则 0h 根收益未定义时为 0 而不是哨兵值（i8 没有 NaN），需要剔除的用 forward return 做掩码。θ 为负或 NaN 报错。恰好 ±θ 落在带内。
triple_barrier(up, down, H)从 t+1 到 min(t+H, 末行) 逐根看，先 ≥ up 为 +1，先 ≤ −down 为 −1，都没有为 0最多 H 根；第二个返回值写明在哪一根决定只看收盘价：最高价穿过 up 但收在下面不算，比盘中止损保守。t 之后的 NaN 跳过而不是结束；t 本身是 NaN 或最后一根时标签 0、决定行 −1。up、down 必须为正有限，H ≥ 1。
pivot_labels(θ)zig-zag：+1 确认的波谷，−1 确认的波峰无上限t 处的拐点只有等后面某根反转够 θ 才能确认，那一根可能任意远。最后一段的候选极值永不确认、为 0。相等的高点在第一根成为拐点。“在 zig-zag 波谷买入”回测非常漂亮，但无法交易。

所有数组都是列主序、长度 n_rows × n_cols；形状不对返回 Error::Broadcast，参数不合法返回 Error::Invariant。“排名”类函数输出 −1 表示“这里没有信号”。
