phasor-expr

因子表达式。把 Qlib 风格的字符串——$close / Mean($close, 20) - 1——编译一次，然后对任意多个面板求值，结果直接是列主序的 Matrix（时间 × 标的）， 可以交给信号层和模拟层。它不是一个通用的解释器：整个因子集被编译成一张去重的依赖图，按标的并行求值，每个标的只需要几条暂存序列。

从第一性原理看：因子为什么要一门语言，又为什么要编译

先不看代码。一个因子是“面板 → 面板”的函数：输入是开高低收量（时间 × 标的），输出是同形状的一张表。要做这件事，有几个问题绕不过去。

1. 为什么不直接写 Rust 函数

研究的节奏是“改一个窗口、换一个分母、再跑一遍”，每次重新编译 Rust 太慢；而且业界大量现成的因子库（Qlib 的 Alpha158 / Alpha360）本来就是字符串。 一门小语言让因子成为数据：可以存进配置、从 Python 传进来、在报告里原样显示，并且和参考实现逐字对照。

2. 因子之间大量重复

Alpha158 里几十个因子都用到 Ref($close, 1)，Mean($close>Ref($close,1), d) 在 CNTP 和 CNTD 里各出现一次；a+b 和 Add(a,b) 是同一个东西。 逐个解释每个因子的语法树，会把同一个子表达式算上几十遍。所以整个因子集应当被编译成一张共享子表达式的有向无环图：节点由“算子 + 输入节点”唯一确定（hash-consing）。

3. 内存应该由“同时活着的中间结果”决定，而不是由节点数决定

357 个节点如果每个都存一整张 2520 × 200 的矩阵，就是 357 × 4 MB。但几乎所有算子都是逐标的的时间序列运算：一个标的的结果从不读另一个标的。 于是可以一次只算一个标的，中间结果只是一条 2520 长的序列（约 20 KB）；再按依赖顺序排好节点，一条中间序列在它最后一个读者之后就可以被复用——像寄存器分配。 Alpha158 最后只需要 17 条暂存序列。

4. 平移不该复制数据

Ref(x, k) 只是“晚 k 行读 x”。把它物化成一条新序列，Alpha360 就要多复制 354 次。正确的做法是把它当成视图：消费者带着偏移量直接读 x。 负的 k 读的是未来，必须真的计算，并且要能被检测出来（uses_future()）——它只能出现在标签里，不能出现在信号里。

5. 错误要在编译期报

窗口是 2.5、分位数是 1.5、Ref 的偏移是一个字段——这些都应该在 compile 时、带着因子名报出来，而不是在算完前 150 个因子之后才在第 151 个上失败。 字段缺失也一样：求值前先解析所有字段，并行部分就没有出错路径。

6. 两个后端互相检验

一个手写的高速后端，和一个尽量直接地翻译成 Polars Lazy 的后端，在同一份 qlib fixture 上都必须通过。两者实现完全不同（增量累加器 vs 逐窗 UDF），同时出错的概率很小。

语言

字段写作 $name（不区分大小写，统一小写）；OHLCV 由 from_ohlcv 提供，其他字段（例如 Alpha158 需要的 vwap）用 with_field 加入。 布尔结果是 1.0 / 0.0。运算符优先级从低到高：

|<&<> < >= <= == !=< + −<* /<一元 + −<**（右结合）

所以 -2**2 是 -(2**2) = -4，和 Python 一样；$a > 1 & $b < 2 是 ($a>1) & ($b<2)。单独的 = 或 ! 是词法错误。

类别函数语义
逐元素Abs Sign Log Not；Add Sub Mul Div Power Gt Ge Lt Le Eq Ne And Or；Greater Less；If(c, a, b)函数写法和运算符写法编译成同一个节点。比较是 NumPy 式的精确比较：和 NaN 比较得 0。Greater / Less 遇 NaN 得 NaN。
平移Ref(x, n)、Delta(x, n)Ref 正数读过去（视图），负数读未来；Delta = x − Ref(x, n)，n 不能为负。
平滑EMA(x, p)p < 1 是 alpha，p ≥ 1 是 span（alpha = 2/(p+1)），0 是扩展窗口（每行重新加权，O(n)）。
滚动 (x, N)Mean Sum Std Var Max Min Med Mad Count Skew Kurt WMA Rank IdxMax IdxMin Slope Rsquare Resimin_periods = 1（qlib 语义：第 0 行就有值）；N = 0 是扩展窗口；NaN 占窗口位置但不参与计算。Std/Var 是样本（ddof = 1）；Rank 是最后一个值在窗口里的分位；IdxMax/IdxMin 从 1 开始。
滚动 (x, N, q)Quantile线性插值，q ∈ [0, 1]。
成对 (x, y, N)Corr Cov只用两边都不是 NaN 的行；Corr 在任一边的标准差 ≤ 2e-5 时为 NaN（qlib 的规则）。

还不支持：截面算子（一行读所有标的，例如截面排名）、跨标的引用、掩码（ARCHITECTURE §5.7、§17.2）。正因为所有算子都只读本标的，图才可以按标的并行。

求值：每个标的一个任务

上面编译出的因子集在一个合成面板上求值（2 个标的 × 80 根 K 线，vwap 由开高低收的均值近似）。求值器和原生后端的语义一致——同样的 min_periods = 1、同样的 NaN 规则、同样的 qlib 特例； 窗口统计用逐窗重算，而原生后端用增量累加器，两者在 1e-9 内一致（eval.rs 的测试正是这样对照的）。

FactorSet::evaluate 在合成面板上，JS 移植

细线是两个标的的 close（右轴），粗线是所选因子（左轴）。“单独求值逐位相同”对应 Rust 测试 each_symbol_evaluates_exactly_as_it_would_alone：一个标的和别的标的放在一起算、还是单独算，结果的每一位都相同——这是按标的并行的前提。

没有锁，也没有 unsafe

每个输出先按列切成 &mut [f64]，第 c 个任务拿走每个输出的第 c 片。任务之间写的内存互不相交，借用检查器就能证明。

页面惰性清零

每个输出单独 vec![0.0; n]，由写入它的线程第一次触碰时才真正清零；原先克隆一个全零缓冲区，串行就要 350 ms。

峰值内存就是输出

中间结果是单个标的的序列（2,520 行约 20 KB），每个线程只有 graph.slots 条。2520 × 500 的 Alpha158 峰值 RSS 约 1.6 GB，几乎全是 158 个输出矩阵。

每 N 行重建一次

加一个、减一个的舍入误差会累积。累加器每 window 行从窗口本身重算一次和，误差最多跨两个窗口；重建是 O(window)、每 window 行一次，总代价仍是 O(n)。

平移求和

值按“与第一个进入空窗口的值之差”求和：价格在 100 附近时，方差就不再是两个大平方数的小差，避免灾难性抵消。

常量窗口检测

qlib 在 Corr 的 va == 0、Rsquare 的 yvar <= 0 处做精确比较。增量和在全等的值上会留下残差，所以 Moments 记录末尾有多少个相同的观测，全相同时报告精确的 0 方差。

有序结构只存整数位置，所以 Quantile / Med / Rank 与对窗口排序的结果逐位相同；每个核心都在 NaN 段、常数段、高价位小波动、纯噪声上与逐窗重算对照（incremental_windows_match_a_full_rescan，容差 1e-9）。

两个后端

ComputeBackend 只有两个方法：name() 和 evaluate(set, inputs)。NativeBackend 是默认；PolarsBackend 在 polars feature 下可用， 长表格式 + .over(symbol)，每批 64 个因子，qlib 特有的算子用 rolling_map 调用和原生后端测试里同一组逐窗函数。它的用途是独立交叉验证，不是性能。

原生 vs Polars（4 线程，3 次取最好；ARCHITECTURE §5.6）。条长是对数刻度

Polars 慢在：每个算子都要重新按标的分组、qlib 算子是 O(window) 的 UDF、批次之间无法共享子表达式、Option<f64> 转换。原生后端的优势主要来自整张图只走一遍、共享节点和视图。

Alpha158 与 Alpha360

alpha158() 和 alpha360() 按 qlib 的 Alpha158DL / Alpha360DL.get_feature_config() 生成表达式并编译：名字、顺序、公式都和 qlib 一致（不含归一化和标签）。 Alpha158 = 9 个 K 线形态 + 4 个当前价格比 + 29 个滚动族 × 5 个窗口（5、10、20、30、60），顺序按族排列（ROC5…ROC60，再 MA5…MA60）。点一个族，把它的五个因子放进上面的编译器。

族窗口公式（d = 窗口）

Alpha360 是 6 个字段 × 60 个滞后：Ref($close, k)/$close、开高低 vwap 同理，成交量除以 $volume + 1e-12。其中 354 个 Ref 都是视图，所以整个 Alpha360 编译后只需要 1 个槽位。 两个集合都需要显式的 vwap 字段（required_fields() 会列出它），都不读未来（uses_future() = false）。

不能绕开的规则

语义跟 qlib 走

min_periods = 1、样本标准差、和 NaN 比较得 0、Corr 的 2e-5 阈值、WMA 的权重包含 NaN 槽位——这些都是 qlib 的行为，不是“更合理”的选择。tests/fixtures/qlib_*.tsv 不能为了让改动通过而重新生成。

新算子先问：它只读本标的吗

按标的并行、每个标的一份 Scratch，都建立在“每个算子只读本标的”之上。截面算子需要把调度切成阶段（阶段内按列并行，阶段之间一次截面），见 graph.rs 模块注释。

uses_future 的因子只能当标签

Ref(x, -k) 读未来。FactorSet::uses_future() 和 Python 的同名方法让调用方在把因子接到信号之前检查它。

参数必须是字面量

窗口、偏移、分位数、EMA 参数都在编译期解析成带类型的算子（Rolling(kind, Window)、Ref(i64)）；这样哈希合并才能识别相同的节点，错误才能在编译期报。
