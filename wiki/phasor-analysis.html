phasor-analysis

分析层。它只读记录，不读模拟状态：从成交记录、收盘价和初始资金重建出资产、现金、净值和收益，再把它们化成指标；把成千上万列的指标按列标签汇总成答案； 并且提醒你，一千组参数里最好的那个夏普，有多少是运气。因为只读记录，向量化层和计划中的事件驱动层用的是同一个分析层。

从第一性原理看：分析层该从哪里读、算什么

先不看代码。一次回测结束后，“它表现得怎么样”这个问题，需要先回答下面几件事。

1. 只从记录重建

模拟循环可以把现金、仓位、净值整条存下来，但一次扫描有几千列，每列再存六条序列，内存就是数据本身的好几倍——而大多数列最后只会被问一个数（夏普）。 反过来，成交记录本身就是完整的账本：现金、仓位、负债都是成交序列的函数。所以只存记录和价格，其他都在被问到时重建。 这也让分析层不依赖“是谁产生的记录”：向量化层和事件驱动层写同一种记录，就共用同一个分析层。仓库的规则也由此而来：任何改变现金或仓位的东西都必须是一条记录。

2. 收益序列要诚实

第一根 K 线的收益要相对初始资金算，否则第一根上的交易成本就看不见了。入金不是收益、出金不是亏损，所以入金要先加进“期初”再算收益。 空头账户的净值可能为负，此时收益的符号要翻转，否则亏损越来越大读起来像是在赚钱。净值从 0 开始时没有比率可算，得到带符号的无穷大。

3. NaN 是缺失，退化是答案

缺一根 K 线不该让整列指标变成 NaN，所以每个归约都跳过 NaN。但另一类特殊值不能跳过：一列从未交易，收益恒为 0、波动为 0，夏普是 +∞——参考实现如此， 而这意味着没有交易的列会排在扫描第一名。这不是 bug，是一个必须让人看见的结果；正确的做法是在排名前把不满足前提的列屏蔽成 NaN。

4. 一千个数还不是答案

扫描产出的是每列一个指标。人们真正问的是“哪个窗口最好”“这个因子在各个标的上都有效吗”——全是“按某一层标签分组、组内归约”。所以列标签放在地基里，分析层用 group_indices 汇总。

5. 最好的那个有多少是运气

试了一千组参数、报告最大的夏普，测到的是一千个噪声估计的最大值。Bailey 与 López de Prado 给出的修正：概率夏普（PSR）考虑样本长度和收益的偏度、厚尾； “N 个毫无价值的试验里最好的那个靠运气能有多高”有近似公式；去偏夏普（DSR）就是拿这个运气上限而不是 0 当基准的 PSR。PBO 则直接估计“样本内的冠军在样本外低于中位数”的概率。

6. 年化因子是一个选择

默认 365（加密市场每天都交易）。日线股票应当约 252；用错会让每个年化数字偏大或偏小约 20%。它和无风险利率、用哪种交易视图、是否计入未平仓交易一起放在 Scoring 里——改它们不需要重跑模拟。

重建链：从成交记录到净值

下面用 tests/fixtures/analysis.tsv 里的 37 个真实情形。每根 K 线的下单量先经过 phasor-exec 内核的移植（价格 = 估值价 = 当根收盘、独立账户）， 得到成交记录；再走 series.rs 的重建链。最下面两行是 vectorbt 给出的净值，以及逐格是否一致。

orders → asset_flow / cash_flow → assets / cash → asset_value → value → returns → 指标
指标（ann = 365）本页重算vectorbt（fixture）一致

累加用 math::add

同一根 K 线上可能有多笔成交，所以 asset_flow / cash_flow 是累加而不是赋值；用容差加法，一根 K 线里的一来一回留下的是精确的 0，而不是 1e-16 的“仓位”。

free_cash 也能从记录重放

free_cash_flow 从成交序列重放内核的 debt 账本（开空冻结 2 × 空头价值、平空按均价释放），所以总敞口 |资产值| / (|资产值| + free_cash) 也不需要从模拟里带出状态。多头列上 cash 与 free_cash 完全相同，所以这个差别要靠做空的 fixture 才能抓住。

多空分开计

一次穿过零的反手不是一步，而是两步：旧方向平掉、新方向开出。long_size / short_size 把它拆开，所以“多头敞口变了多少”在反手的 K 线上也有答案。

过拟合：最好的那个有多少是运气

生成 N 个毫无价值的策略（每个都是均值为 0 的随机收益），算出每个的单期夏普，取最大的那个。expected_max_sharpe(N, V) 预测这个最大值靠运气能有多高； 概率夏普（PSR，基准 0）说“它的真实夏普大于 0”的概率，去偏夏普（DSR）把基准换成运气上限。下面三个函数是 robust.rs 的移植（norm_cdf / norm_ppf 与 Rust 测试里的已知值一致）。

probabilistic_sharpe · expected_max_sharpe · deflated_sharpe，JS 移植

单期夏普

这个模块里所有夏普都是未年化的单期比率（均值 / 样本标准差），公式就是按这个单位写的；传给 deflated_sharpe 的试验夏普必须和收益同一单位。

PSR 的分母

1 − γ₃·SR + (γ₄ − 1)/4 · SR²，γ₃ 是偏度、γ₄ 是（非超额）峰度，都用总体中心矩。负偏、厚尾会让同样的夏普更不可信。分母不为正时返回 NaN 而不是一个看起来自信的概率。

PBO（CSCV）

把行切成偶数个块（最多 16 个），枚举所有“一半做样本内、一半做样本外”的组合；对每种切法，看样本内冠军在样本外的相对名次。冠军落在中位数以下的比例就是 PBO。纯噪声约 0.5。

stats()：一张有顺序、有标签的表

stats(input, select) 回答人们打开回测时的第一个问题：“它表现得怎么样”。顺序、标题和百分比缩放都是参考实现的——包括最大回撤以正的百分比报告，而这个 crate 里其他回撤数字都是负的。 点标签筛选（Select::with_tags）；没被选中的指标根本不会被计算。缺输入（没有基准、没有价格）时是 Value::Missing，打印成 “—”，而不是一个像测量值的 0。

Portfolio：只存四样东西

存什么

成交记录（含 CashRecords）、收盘价（借用，扫描的价格矩阵是系统里最大的东西）、初始资金、形状，以及可选的基准。from_records、from_grouped_records（共享资金分组）、from_borrowed（Python 层借入一份 Cache），另有直接跑模拟的 from_orders / from_signals。

算什么

assets、cash、free_cash、asset_value、value、returns、deposits、gross / long / short / net exposure、allocations、trades、drawdowns……每个都在第一次被问到时算一次，存进 Cache 里对应的 OnceLock。不是 RefCell，所以多个线程可以从同一个 Portfolio 并行算不同列的指标。

账户分组

仓位和交易始终按标的；现金、净值和收益类指标按共享资金分组，初始资金每组只算一次。独立列就是大小为 1 的组。

Scoring

ann_factor = 365、risk_free = 0、trades_type = ExitTrades、incl_open = false。改评分方式用 with_scoring，缓存的重建结果仍然有效，不需要重跑模拟。

文档与实现的差距：lib.rs 的 “Status” 一节仍写着“共享资金和组级 portfolio 尚未实现”。但 Portfolio::from_grouped_records、portfolio.rs 的 “Account groups” 说明、stats.rs 的“按账户聚合”以及 tests/shared_accounts.rs 都表明它已经实现了。

不能绕开的规则

改变现金或仓位的必须是记录

分析层只从记录重建。一个只改了模拟状态、没有写记录的现金流（利息、分红、资金费），在这里就不存在——净值会悄悄错。入金、收益、分红都走 CashRecords。

排名之前先屏蔽

从未交易的列夏普是 +∞，会成为 best_column。这一层故意不替你丢掉它；调用方要说清楚在排什么：把不满足前提（例如 0 笔交易）的列设成 NaN。examples/sweep.py 和 crates/phasor/tests/sweep.rs 固定了两种结果。

拼写也是语义

百分位必须写成 lower·(1 − m) + upper·m（Numba 的写法），不是教科书的 lower + m·(upper − lower)；最后一位的差别正是 fixture 抓到的。冗余的护栏（Sharpe 的 len < 2）也保留，因为参考实现有，而且读者看不出哪个有用——注释说明了哪个有用。

基准按列，不按扫描

列 c 的基准是“该列标的”的买入持有收益，基准数组要和标的一样 tile。把一个标的的基准用于所有列是这一层检测不到的错误。fixtures/*.tsv 不能为了让改动通过而重新生成。
