phasor-indicators

技术指标，以及把参数扫描变成一次调用的那个约定。三个窗口 × 四个标的跑一次均线，返回的不是三份四列的结果，而是一份十二列的结果： 模拟器把它当作十二个互不相关的列，分到多个核上跑，完全不知道其中八列共享同一个标的。列标签负责把结果归因回“哪个窗口、哪个标的”。

从第一性原理看：指标库真正要解决的问题

均线、RSI、MACD 的公式教科书上都有，算术不是难点。一个给回测引擎用的指标库，要先回答下面这些问题。

1. 指标是有名字的滚动窗口

MA 是滚动均值，MSTD 是滚动标准差，BBANDS 是两者的线性组合，RSI 是涨跌两条序列各自的均值之比，STOCH 是滚动最高最低之间的位置，MACD 是两条均线之差再平滑，ATR 是真实波幅的均值。 所以窗口的语义（预热期、NaN、累加形式）应当只在 phasor-generic 里决定一次，这里只负责组合：哪个窗口喂给哪个均值。

2. 预热期必须是 NaN

20 根均线在第 19 根之前没有定义。这里所有均值都用 minp = window：一个在窗口没满时就开始报数的指标，报的是另一个指标。 这和 phasor-expr 正好相反——qlib 的因子用 minp = 1，从第 0 根就有值。两种都对，但不能混用而不自知。

3. 参数和标的是同一个轴

扫描参数的朴素做法是一个外层循环：每组参数跑一次。但模拟器本来就把每一列当成独立的模拟；把“参数组合 × 标的”展平成一个列轴，整个扫描就变成一次调用、一张矩阵， 并行完全免费。代价是必须固定一个布局，让下游能从列下标算回参数：col = 组合下标 × 标的数 + 标的下标。

4. 扫描里大量计算是重复的

3 个快线窗口 × 3 个慢线窗口的 MACD 网格是 9 个组合，但最多只有 6 条不同的均线；BBANDS 的 3 个窗口 × 4 个 alpha 是 12 个组合，均值和标准差却只取决于窗口，只要算 3 次。 所以每个指标都按“真正决定这个中间结果的参数”做缓存——在宽网格上，这省掉的是大部分工作。

5. 交叉还是配对，必须由调用方说

三个窗口和三个 alpha，是 3 组还是 9 组？参考实现用一个带默认值的开关决定，这是常见的意外来源——没有哪个默认值对两种情况都对。这里不提供开关： combinations(&[3, 3]) 显式生成笛卡儿积（最后一维变化最快），直接传等长的参数列表就是配对。

6. 退化的读数要从算术里自然得出

全涨的序列 RSI 恰好是 100：跌幅均值为 0，涨跌比是 +∞，100 − 100/(1+∞) = 100。横盘时 STOCH 是 0/0 = NaN。第一根 K 线没有前收盘，真实波幅退回到当根的高低差。 这些都不写成特例，而是让 IEEE 754 的算术自己给出——这也是容差层要把无穷当成有意义的值的原因之一。

最后一维变化最快

combinations(&[3, 2]) = [0,0] [0,1] [1,0] [1,1] [2,0] [2,1]，和 Python 的 itertools.product 一致。空的 sizes 给一个空组合（不扫描也是一次运行），任何一维为 0 则什么都没有。

布局是契约

模块注释原话是“是契约，不是惯例”：Indicator 的输出不经任何重排就交给模拟器，共享资金的 group_lens 也依赖同一组参数的列相邻。见 phasor-core · 列轴。

两种错误

参数层描述的组合数不一致，或者某个参数层和输入层（symbol）重名，sweep_columns 返回 Error::Invariant。不扫描的指标（OBV）也有标签：只有 symbol 一层。

缓存：宽网格省掉的是大部分工作

同一个扫描里，缓存键只包含真正决定那个中间结果的参数。格子是每个组合需要的中间结果：橙色是第一次算，绿色是从缓存里取。

验证

matches_the_reference_indicators

480 行，每行一个指标、一种情形、一组参数——这样不一致时报出的是参数组合，而不是扫描里的列下标。比较用对哨兵友好的 agree（NaN 对 NaN、同号无穷对同号无穷，其余 is_close）。fixture 由 tests/parity/generate_indicators.py 对 vectorbt 生成，固定 adjust = false、ddof = 0。

a_sweep_equals_its_parts

窗口 [2, 3, 5, 2] 一次扫描，每个组合的每一列必须和单独运行逐位相同、落在 column_of 说的位置；重复的窗口 2 是独立的组合、值相同（由缓存提供）；标签能说出哪列是哪个窗口。这个页面的移植同样通过。

the_fixtures_still_cover_the_degenerate_readings

要求 fixture 里仍然有 RSI 恰好为 100 和 0 的读数（精确比较，近似会把附近的普通值也算进去）、横盘 STOCH 的 NaN，以及所有输入情形。防止有人“清理”fixture 时把最有价值的行删掉。

窗口函数在下面一层验证

每个窗口函数已经在 phasor-generic 里逐个对照过（1,650 行）；这里测的是组合：哪个窗口喂给哪个均值、哪个输出叫什么、退化的读数从哪来。

不能绕开的规则

布局只能是 comb·n + s

新指标必须用 sweep_columns 建标签、用 place / column_of 放输出。参数层 repeat、标的层 tile，换了顺序，group_by 的汇总和共享资金的分组都会悄悄错。

缓存键要恰好是决定因素

键里少了一个真正影响结果的参数，就会把错误的中间结果发给别的组合；多了一个无关参数，只是少省一些。新增参数时先问：它改变的是缓存的那一层，还是缓存之后的那一步？

不要给退化读数写特例

RSI 的 100、STOCH 的 NaN、首根 TR、OBV 首根都来自算术本身，并且被 fixture 钉住。加一个 if down == 0 { 100 } 看起来更清楚，但会在 NaN 输入上改变行为。

窗口语义在 generic 里改

这里不碰预热期、NaN 规则、累加形式；它们属于 phasor-generic，并由那边的 fixture 钉住。tests/fixtures/*.tsv 不能为了让改动通过而重新生成。
