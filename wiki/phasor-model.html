phasor-model

领域模型：定点价格和数量、交易标识、K 线，以及驱动执行状态机的枚举。 执行枚举对齐向量化参考引擎，因为验收标准是成交语义逐位一致。 价格和标识对齐阶段 2 的策略 API 形状：定点整数加按品种的精度、可复制的标识。两边如果形状不一致，每次调用都要转换。

4模块：types、ids、enums、bar。实现是手写的，不从参考项目拷代码
8个 crate 在 src 里直接使用。测试和 examples 不计
1条虚线：Cargo.toml 声明了 phasor-core，源码没有引用

点一个节点

模块说明它被谁使用；crate 说明它拿 phasor-model 的哪一部分去做什么。

crate 内部

四个模块里只有 bar 引用另外两个：Bar 和 BarType 带 InstrumentId，Bar 的价格和成交量是 Price、Quantity。enums 不引用它们。定点类型也不引用枚举，方向放在 OrderSide 里，不放进数量的符号。

内部依赖：bar 使用 ids 和 types；enums 独立

OhlcvPanel 虽在 bar 模块里，字段是 Vec<f64>，不持有 Bar 或 Price。阶段 1 读的是这块列主序面板。

四个模块做什么

types

价格和数量是带精度的缩放整数，不是 f64。原始值是 value * 10^precision，默认精度 9。Price::UNDEF 用 i64::MAX，Price::ERROR 用 i64::MIN，避免在最内层循环里为 Option 付一次分支。没有换算方法：不同 precision 的同名义值不相等，Ord 先比 raw 再比 precision。

ids

Symbol 和 Venue 把名字收进 Arc<str>。InstrumentId 是两者的组合，显示成 SYMBOL.VENUE。相等按字符串内容，不按分配地址。类型保持可克隆、可比较，以后换内部存储不必改调用点。

enums

全部 #[repr(i8)]。判别值写进记录数组，再被 Python 和对照测试读回来，改一个就是记录格式的破坏性变更。OrderStatus::Rejected 是正常返回值，不是 Err。原因在 StatusInfo，describe 给人看，from_discriminant 从存盘的 i64 还原；-1 表示已成交、没有原因。

bar

Bar 是一根 K 线，价格用 Price，带 ts_event（交易所收盘）和 ts_init（引擎可见）。回放按 ts_init，这是唯一不会泄漏未来的时间。OhlcvPanel 是四条价格加成交量的列主序 f64，阶段 1 止损分趟读 open、high、low，所以不用结构体数组。BarType 标识一条序列，不是品种本身。

定点值。Price 和 Quantity 都带着自己的 precision，类型别名决定以后加宽时改一处

标识与 K 线。Bar 拥有定点价格；OhlcvPanel 是另一条布局，不拥有 Bar

执行枚举。全部 repr(i8)，判别值即记录里的存储值。OrderStatus 在被忽略或拒绝时才带 StatusInfo

来源：crates/phasor-model/src/enums.rs。十七个枚举都是 repr(i8)。判别值写进记录数组，测试把其中几个钉死，改数字就是记录格式的变更。

核心类型

成员与 crates/phasor-model/src 一致。crate 根再导出 Bar、BarType、OhlcvPanel 和全部枚举。

Price、Quantity

types.rs · 缩放整数。阶段 1 的模拟循环仍用 f64；这两个类型由门面再导出

成员含义
PriceRaw / QuantityRaw别名，现在是 i64 和 u64。高精度（例如 18 位链上数量）把价格改成 i128 时，改的是别名。
PRECISION / SCALAR默认 9 位小数。SCALAR 是 1e9 的 f64，给需要标度的调用方用。每个实例仍可以带自己的 precision。
Price::UNDEFraw = i64::MAX，precision 0。表示没有价格。和 0、和 NaN 都不同。
Price::ERRORraw = i64::MIN，precision 0。表示价格算不出来。is_sentinel 对这两个 raw 返回 true。
from_raw / raw / precision唯一的构造和读取路径。没有从 f64 来回转换的方法，也没有加减。
Quantity无符号。没有哨兵。空头还是多头由 OrderSide 表示，数量本身不为负。

Symbol、Venue、InstrumentId

ids.rs · FromStr 的错误类型是 String

成员含义
Symbol::new / Venue::new把名字放进 Arc<str>。as_str 借出内容。同名比较相等。
InstrumentId::new直接组装两部分，不重新解释字符串。
from_parts(symbol, venue)要求两边都非空，且 venue 不含 .。然后走 SYMBOL.VENUE 的解析。
FromStr从右边第一个 . 切开。任一侧为空，或出现空白、控制字符、/、\，都拒绝。品种名因此可以含点，场地名不能。
DisplaySYMBOL.VENUE。

Bar、BarType、OhlcvPanel

bar.rs · UnixNanos = u64

类型含义
Bar一根 K 线。四个价格是 Price，成交量是 Quantity，品种是 InstrumentId。ts_event 是交易所收盘时刻，ts_init 是引擎看得到它的时刻。其他 crate 的 src 目前不读这个结构体。
OhlcvPanel五块 Vec<f64> 加上 n_rows、n_cols，派生 Default。列主序，一列的历史是连续的。因子输入和数据准备读的是它。
BarType一条序列的身份：品种、步长、聚合方式、价格类型、来源。显示为 SYMBOL.VENUE-STEP-AGGREGATION-PRICE-SOURCE。
BarType::from_str从右边按 - 切四刀，剩下的整段再解析成 InstrumentId，所以品种名可以含 -。step 必须非 0。来源只接受 INTERNAL、EXTERNAL。价格只接受 BID、ASK、MID、LAST。聚合方式是固定的时间桶或 TICK / VOLUME / VALUE 及其 IMBALANCE、RUNS。

枚举

enums.rs · 全部 Copy + Eq + Hash + repr(i8)。只有 StatusInfo 有方法

枚举判别值含义
SizeTypeAmount 0 · Value 1 · Percent 2 · TargetAmount 3 · TargetValue 4 · TargetPercent 5请求规模怎么解释。Amount 是单位个数，也是级联的终点。Value 是现金，要除以估值价。Percent 是可用现金的比例，落在 [0, 1]。三个 Target 是相对当前持仓或组合价值的目标，先变成差额。改写发生在 phasor-exec，不在这个类型里。
DirectionLongOnly 0 · ShortOnly 1 · Both 2一列允许哪一侧。LongOnly 拒绝做空，ShortOnly 拒绝做多，Both 可以穿过零反手。
OrderSideBuy 0 · Sell 1这笔订单实际打在哪一侧。记录里的 side 存的就是这个判别值。
OrderStatusFilled 0 · Ignored 1 · Rejected 2Filled 是全部或部分成交。Ignored 是无事可做。Rejected 是做不了，原因另记。三者都是返回值。
StatusInfo0 SizeNaN … 13 PartialFill十四条原因，见类图上的名字。describe 返回英文短句。from_discriminant 接受 i64，因为记录数组加宽了存储；-1 和任何未列出的值返回 None。
AccumulationModeDisabled 0 · Both 1 · AddOnly 2 · RemoveOnly 3同向信号遇到已有持仓时：不动、可加可减、只加、只减。
ConflictModeIgnore 0 · Entry 1 · Exit 2 · Adjacent 3 · Opposite 4同一根 K 线上入场和出场同时出现。Adjacent 让贴近当前持仓的一侧赢，Opposite 让相反的一侧赢。
DirectionConflictModeIgnore 0 · Long 1 · Short 2 · Adjacent 3 · Opposite 4多头信号和空头信号同时出现。Adjacent / Opposite 相对当前持仓的方向。
OppositeEntryModeIgnore 0 · Close 1 · CloseReduce 2 · Reverse 3 · ReverseReduce 4入场信号和持仓方向相反。Close 只平仓。Reverse 平掉再开反向。带 Reduce 的两个在平仓或反手之后再走累积规则。
StopEntryPriceValPrice 0 · Price 1 · FillPrice 2 · Close 3开仓时止损锚定哪一个价：估值价、请求价、实际成交价、这根 K 线的收盘价。
StopExitPriceStopLimit 0 · StopMarket 1 · Price 2 · Close 3止损触发后以什么价成交。StopLimit 是止损价本身，不加滑点。StopMarket 在止损价上加滑点。
StopExitModeClose 0 · CloseReduce 1 · Reverse 2 · ReverseReduce 3触发后对持仓做什么。语义和 OppositeEntryMode 里同名的变体一样，只是起因是止损而不是反向信号。
StopUpdateModeKeep 0 · Override 1 · OverrideNaN 2新的止损值要不要替换已经生效的。Keep 保留旧的。Override 替换，但新值是 NaN 时不动。OverrideNaN 连 NaN 也接受，NaN 用来清除止损。
TradeDirectionLong 0 · Short 1一笔成交记录在哪一侧。和 OrderSide 不是同一个枚举：后者是买单或卖单，前者是这笔交易的多空。
TradeStatusOpen 0 · Closed 1模拟结束时这笔交易是否还开着。
TradesTypeEntryTrades 0 · ExitTrades 1 · Positions 2同一套记录的三种看法。EntryTrades 每次入场一条，出场按 FIFO 分回。ExitTrades 每次出场一条，入场成本平均进去。Positions 把共享父单的成交合成一个持仓。
CashFlowKindDeposit 0 · Earning 1 · Dividend 2没有成交却动了现金。Deposit 是开盘的入金或出金，改变价值，不算收益。Earning 是收盘计入的利息、费用或其他损益。Dividend 是开盘持仓乘以每股分红，空头支付它。后两种算进收益。

三条不能绕开的规则

判别值是记录格式的一部分。enums.rs 的测试把 SizeType::TargetPercent = 5、Direction::Both = 2、OrderStatus::Rejected = 2、StatusInfo::PartialFill = 13、TradesType::Positions = 2 和三种 CashFlowKind 钉死。改数字就要同时改已经写出去的记录和对照夹具。 
OrderStatus::Rejected  !=  Err          // 拒单是状态，不变量破坏才是 Error
Price::UNDEF.raw        ==  i64::MAX     // 不是 Option，也不是 NaN
OhlcvPanel.close        :   Vec<f64>     // 阶段 1 不走 Price
ts_init                                  // 回放排序；ts_event 是交易所时间

谁依赖它，用来做什么

crate用到的模块用来做什么

phasor 的 prelude 再导出全部枚举、InstrumentId、Symbol、Venue、Price、Quantity。pub use phasor_model as model 让其余类型从 phasor::model 出去。prelude 不导出 Bar、BarType、OhlcvPanel。
