phasor-generic

数组层。指标是有名字的滚动窗口，因子表达式是带解析器的滚动窗口，好几个分析指标是末尾多一步除法的滚动窗口——把它们放在一处，语义就只决定一次。 这一层的算术都很简单，难的是边界：窗口没满时报不报数、遇到 NaN 怎么办、哪些函数会偷看未来、浮点累加的最后几位是否和参考实现一致。

从第一性原理看：一个滚动窗口要先决定什么

先不看代码。“过去 20 根 K 线的均值”是一行公式；写成函数之前，至少有六件事要先定下来，而每一件选错都会悄悄改变策略看到的信号。

1. 窗口没满时报不报数（min_periods）

20 根均线在第 0 根 K 线上只有 1 个观测。如果这时就输出一个数，它和第 20 根以后的值放在同一个数组里，看起来完全一样，但含义完全不同—— 在它上面入场的策略，交易的是另一个信号。所以每个窗口函数都要一个 minp：至少有几个非 NaN 观测才输出数字，否则输出 NaN。保守的默认是 minp = window。

2. NaN 是缺失的信息，不是失败的计算

停牌、数据缺口、指标预热期都会产生 NaN。让它“传染”整个窗口（一个 NaN 就让 20 根的结果都变 NaN）会把一个小缺口放大成一大段空白；当成 0 又会把均值往下拉。 正确的语义是：NaN 缩小窗口——它不计入总和，也不计入观测数，只要剩下的观测数还够 minp，就照常报数。

3. 增量计算和重新求和不是同一个答案

均值和标准差用前缀和：每根 K 线一次减法，O(1)。重新对窗口求和是 O(window)，而且在浮点里最后几位不同——当序列跨越很多个数量级时（1e8 和 1e-8 交替）， 差别可以到整个数值。下游的阈值比较只要差一位就可能翻转。要和参考实现逐位对齐，就必须用和它一样的累加形式。

4. 最大值不能“减掉”离开窗口的值

和不一样，最大值没有逆运算。但如果一根 K 线被后来更大的一根“压住”，它就再也不可能成为最大值，可以永远丢掉。于是维护一个单调队列： 每根 K 线进队一次、出队一次，均摊 O(1)，而且结果是比较出来的，和重新扫描窗口逐位相同。

5. 前瞻要标出来，而不是禁止

往回平移（bshift）和往回填充（bfill）按定义读取未来：第 i 根的结果用到了第 i 根之后的数据。它们有正当用途（给训练集打标签）， 所以不删，但必须在名字和文档里写明，并且永远不能出现在价格和信号之间。

6. 对照组需要可复现的随机数

真实价格无法区分“找到了优势”和“拟合了噪声”，因为真实过程未知。漂移为 0 的几何布朗运动按构造没有优势，在它上面跑出漂亮夏普的策略，测到的是自己的过拟合。 这样的对照组必须可复现：每个随机数是 (seed, row, col) 的纯函数，第 c 列和总共生成多少列无关。

标准差的护栏和一个真 bug

有效观测数等于 ddof 时输出 NaN；展开式在常数序列上会抵消成极小的负数，所以先 abs() 再开方——它防的是 NaN，不保证 0：常数 0.1 的第 4 根仍是 2.28e-9，和参考实现一致（选 constant 序列看）。最初的移植把 len * (mean * mean) 写成 len * mean * mean，结合顺序变成 (len * mean) * mean：常数序列上是精确 0 和 1.07e-9 的差别，被单元测试抓到。

expanding 是窗口等于长度

expanding_mean_1d 就是 rolling_mean_1d(a, len, Some(minp))，所以 minp > len 会报错。代码注释承认这未必合理，但这是参考实现的行为，悄悄截断会是无声的分歧。

rolling_apply_1d 的两半

通用回调版本：minp 数的是非 NaN 个数，但回调拿到的是含 NaN 的整窗。phasor-analysis 的滚动指标都走它，每个指标自己处理 NaN，所以滚动形式和标量形式在满窗上总是一致。

单调队列：rolling_max 怎么做到 O(1)

队列里存下标，对应的值从队首到队尾严格递减（求最小值时递增）。新值进来时，从队尾弹出所有“不比它大”的候选——它们被新值压住，永远不会再是最大值； 窗口滑过时，如果队首正好离开窗口就弹出。队首永远是当前窗口的最大值。拖动滑块逐根看。

红色格子是用到了未来数据的输出：第 i 根的值依赖第 i 根之后的输入。改序列和 n 看看。

elementwise.rs，JS 移植

ffill 用第 0 个元素做种子，所以开头的 NaN 保持 NaN——后面没有东西可以往前带。用 NaN 做种子结果完全相同（种子只在第 0 个元素本身是 NaN 时才被读到），变异测试也确认这个变异会存活；保留参考实现的写法是因为它说出了意图。

交叉：一个三状态的状态机

crossed_above_1d(a, b, wait) 有三条规则容易写错：必须先严格在下方（一开始就在上方的序列永远不算交叉）；相等只重置计数、不清除“曾在下方”的记忆， 所以碰到之后再上穿也算；NaN 重置一切，数据缺口不能制造一次跨越缺口的交叉。wait 让信号在交叉之后第 wait 根才触发，前提是一直待在上方。

合成路径：没有优势的对照组

gbm 用一步的精确解 S·exp((μ − σ²/2)dt + σ√dt·Z)，不是欧拉近似，所以对数收益严格服从均值 (μ − σ²/2)dt、标准差 σ√dt 的正态分布； μ = 0 时价格期望不变。每个正态随机数由 Box–Muller 从两个均匀数得到，均匀数来自 SplitMix64 对 (seed ⊕ salt, row, col) 的三次链式混合——链式而不是异或， 所以 (row, col) 和 (col, row) 不会撞。

gbm / random_walk，JS 移植（SplitMix64 用 BigInt 精确实现；Math.log / cos / exp 与 Rust 的 libm 可能差一个 ulp）

改“列数”：第 0 列的路径不变——它只依赖 (seed, row, 0)，与总共要了多少列无关。ohlc_from_close 在同一布局上生成开高低：开盘 = 上一根收盘，高 = max(o,c) + |max(o,c)|·spread·U，低同理，所以即使随机游走穿过 0，也保持 low ≤ min(o,c) ≤ max(o,c) ≤ high。

目前没有调用方：ARCHITECTURE §2.3 把合成价格列为这个 crate 的职责，但 gbm、random_walk、ohlc_from_close 在工作区的 src/、示例和 Python 包里都没有被调用，Python 层也没有绑定它们。 它们和 rolling / elementwise 不同，不是参考实现的移植，所以不在 generic.tsv 里；验证靠自己的性质测试（同种子逐位相同、列独立、对数收益的均值和方差、OHLC 不等式）。

累加形式跟参考实现走

均值和标准差必须用前缀和那种写法，EWM 不能换成 mul_add，值不变时必须跳过更新。“更准”的写法会改变最后几位，进而改变下游阈值比较的结果。tests/fixtures/*.tsv 不能为了让改动通过而重新生成。

想清楚 minp 再调用

indicators 用 minp = window（保守）；phasor-expr 有意用 minp = 1（qlib 的语义：从第 0 根就出值）。两者都对，但不能混用而不自知——它们在预热期给出的是不同的信号。

前瞻函数不进信号路径

bshift、bfill 只用于离线打标签；它们出现在价格和信号之间就是未来函数。代码评审里看到它们，第一个问题就是“这个结果会不会被交易”。

浮点相等是有意的

交叉里的 a == b、EWM 里的 weighted_avg != cur 都局部 #[allow(clippy::float_cmp)] 并写了理由：相等是一个独立的状态，加容差会凭空造出一条“既不在上也不在下”的带。
